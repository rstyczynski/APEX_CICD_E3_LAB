# E.4 release participation

This accepted mainline note is the harmless later-baseline fixture for E.4. The A/B/C developer branches began before this document was added. A later release branch intentionally inherits it from current main.

The Release Manager will announce the candidate branch in a GitHub planning issue. A and C opt in with PRs targeting that branch; B defers and keeps its source and native staged work. Readiness, checks and dependency review determine admission separately from participation. The candidate must retain this inherited baseline, A/C intent and B's exclusion before promotion, native numbered release and deliberate central synchronization.

This lab is operated by one Codex session using isolated PDBs and concurrent SQLcl processes. Roles and process overlap do not establish three-human team concurrency. Source changes do not deploy automatically.
